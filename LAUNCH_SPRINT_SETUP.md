This file covers the earlier Cloudinary/Safepay/Resend launch sprint. For the current inventory, collections, discounts, payment-method administration and bulk catalog update, read `TECH_COMMERCE_OPERATIONS.md` and `UPDATE_EXISTING_DEPLOYMENT.md`.

# Launch Sprint Setup — Images, Payments, Tracking, and Email

This package implements requested items 2–6:

1. Signed Cloudinary product-image uploads in the admin product editor
2. Safepay hosted checkout for PKR orders
3. HMAC-verified and idempotent Safepay webhooks
4. Carrier, tracking number, tracking URL, ETA, and fulfilment timestamps
5. Resend transactional emails for order received, payment confirmed, shipped, delivered, and cancelled

## Security boundary and payment behavior

- Product files upload directly from the authenticated admin browser to Cloudinary using a short-lived signature generated by the backend. The Cloudinary API secret is never sent to the browser.
- The storefront redirect from Safepay never marks an order paid.
- Only a Safepay webhook with a valid `X-SFPY-SIGNATURE` can set `paymentStatus=PAID`.
- The webhook checks the Safepay merchant API key, PKR currency, charged amount, order reference, and duplicate event ID.
- Safepay may send multiple failed-attempt events for one checkout tracker. Those attempts are logged but do not close the order, because the shopper may retry the hosted checkout.
- Admins cannot manually change an order to `PAID`.
- Shipping requires a paid order plus carrier and tracking information.
- Email sends are idempotent per order/event through `NotificationLog`.

## Deliberately out of scope

Security follow-up: the seed and reset scripts now require `SEED_ADMIN_EMAIL` and `SEED_ADMIN_PASSWORD` and fail safely if either is missing. Keep those values private in the backend Vercel project and rotate any credential that was previously exposed.

## 1. Deploy the database migration and code

Commit the updated monorepo to the existing GitHub repository. Deploy the backend first:

```text
Vercel project: ecom-backend
Root Directory: apps/backend
Build Command: npm run vercel-build
```

`vercel-build` runs:

```text
prisma generate
prisma migrate deploy
prisma db seed
```

The new migration creates payment events, media assets, notification logs, and the new order payment/shipping fields.

After deployment, verify:

```text
https://ecom-backend-nine-blush.vercel.app/health
```

Expected result:

```json
{
  "status": "ok",
  "database": "connected"
}
```

Then redeploy `ecom-admin` and `ecom-storefront` so their new UI code is active.

## 2. Configure Cloudinary image uploads

Create or open a Cloudinary product environment and copy its Cloud name, API key, and API secret.

Add these variables only to the **ecom-backend** Vercel project:

```env
CLOUDINARY_CLOUD_NAME=your-cloud-name
CLOUDINARY_API_KEY=your-api-key
CLOUDINARY_API_SECRET=your-api-secret
CLOUDINARY_FOLDER=cosmictech/products
```

Do not put `CLOUDINARY_API_SECRET` in `ecom-admin`, GitHub, or any `VITE_` variable.

Flow:

1. An authenticated admin requests `POST /api/admin/uploads/signature`.
2. The backend signs the timestamp and target folder.
3. The browser uploads the file directly to Cloudinary.
4. The browser registers the returned asset through `POST /api/admin/media`.
5. Product and variant records store the Cloudinary HTTPS URL.

Current UI limits are 12 MB per selected file and 12 gallery images per product.

## 3. Configure Safepay sandbox checkout

Create or open a Safepay sandbox merchant account and obtain:

- Secret key
- Merchant API key
- Webhook signing/shared secret

Add these variables to **ecom-backend**:

```env
PAYMENT_PROVIDER=safepay
SAFEPAY_ENVIRONMENT=sandbox
SAFEPAY_SECRET_KEY=your-sandbox-secret-key
SAFEPAY_API_KEY=your-sandbox-api-key
SAFEPAY_INTENT=CYBERSOURCE
SAFEPAY_WEBHOOK_SECRET=your-sandbox-webhook-secret
SAFEPAY_WEBHOOK_SECRET_PREVIOUS=
STOREFRONT_URL=https://cosmictech.digital
```

`SAFEPAY_INTENT` accepts `CYBERSOURCE` or `MPGS`, depending on the channel enabled for the merchant account.

### Add the webhook endpoint

In the Safepay sandbox dashboard, create a webhook endpoint:

```text
https://ecom-backend-nine-blush.vercel.app/api/webhooks/safepay
```

Subscribe it to:

```text
payment.succeeded
payment.failed
payment.refunded
```

Copy the endpoint signing/shared secret into `SAFEPAY_WEBHOOK_SECRET`, then redeploy the backend.

During a secret rotation, keep the old secret temporarily in:

```env
SAFEPAY_WEBHOOK_SECRET_PREVIOUS=old-secret-1,old-secret-2
```

Remove old secrets after Safepay has fully switched to the new one.

### Payment state rules

```text
Order created              -> status PENDING, paymentStatus PROCESSING
Verified payment.succeeded -> status PAID, paymentStatus PAID
payment.failed attempt     -> event logged; order remains retryable
Full payment.refunded      -> paymentStatus REFUNDED
```

The backend validates the successful event amount in the currency's lowest denomination and requires `PKR`.

Stay in sandbox until a full test order reaches `PAID` through the webhook. For live payments, use live credentials and switch:

```env
SAFEPAY_ENVIRONMENT=production
```

Do not switch only the environment name while leaving sandbox keys or webhook secrets in place.

## 4. Configure Resend transactional email

Use a sending subdomain to isolate transactional-email reputation, for example:

```text
updates.cosmictech.digital
```

In Resend:

1. Add `updates.cosmictech.digital` as a sending domain.
2. Copy the SPF/DKIM records Resend supplies.
3. Add those exact records in Hostinger DNS.
4. Wait until Resend shows the domain as verified.
5. Create an API key with sending permission.

Add to **ecom-backend**:

```env
RESEND_API_KEY=re_your_api_key
EMAIL_FROM=Cosmic Tech <orders@updates.cosmictech.digital>
STORE_NAME=Cosmic Tech
SUPPORT_EMAIL=support@cosmictech.digital
STOREFRONT_URL=https://cosmictech.digital
```

The `EMAIL_FROM` domain must be a verified Resend domain/subdomain.

Email failures never roll back an order or payment. Each attempt is recorded in `NotificationLog` as `SENT` or `FAILED` so it can be diagnosed in PostgreSQL and the Resend dashboard.

## 5. Configure shipping totals

Backend values are authoritative:

```env
FREE_SHIPPING_THRESHOLD=2500
FLAT_SHIPPING_RATE=300
```

Use matching display values in **ecom-storefront**:

```env
VITE_FREE_SHIPPING_THRESHOLD=2500
VITE_FLAT_SHIPPING_RATE=300
```

The server recalculates item prices and shipping. The browser's displayed total is not trusted.

## 8. End-to-end sandbox test

1. Sign in to `https://admin.cosmictech.digital`.
2. Edit a product and upload two images from the computer.
3. Reorder the images and save the product.
4. Confirm the images appear on `https://cosmictech.digital`.
5. Create a customer account using an inbox you can inspect.
6. Add an in-stock variant to the cart.
7. Place the order and complete Safepay sandbox checkout.
8. Confirm the success page says the payment is being verified rather than declaring it paid immediately.
9. Open the customer account page. It polls pending payments; the order should become `PAID` after the verified webhook arrives.
10. Open the same order in Admin → Orders.
11. Add carrier, tracking number, optional HTTPS tracking URL, and ETA.
12. Save shipment details; the order becomes `SHIPPED` and sends the shipping email once.
13. Mark the order delivered and confirm the delivery timestamp/email.
14. Check Safepay webhook logs, Resend email logs, and Vercel function logs for the complete transaction.

## 9. Troubleshooting

### Checkout says Safepay is not configured

Confirm all required backend values exist and redeploy:

```env
PAYMENT_PROVIDER
SAFEPAY_ENVIRONMENT
SAFEPAY_SECRET_KEY
SAFEPAY_API_KEY
SAFEPAY_INTENT
SAFEPAY_WEBHOOK_SECRET
STOREFRONT_URL
```

### Payment remains PROCESSING

- Confirm the webhook URL exactly ends in `/api/webhooks/safepay`.
- Confirm the webhook uses the same sandbox/live account as the checkout keys.
- Confirm `payment.succeeded` is subscribed.
- Check backend logs for signature, merchant-key, amount, currency, or order-reference errors.
- Do not attempt to fix this by manually marking the order paid.

### Webhook receives 401

The HMAC secret or raw payload signature does not match. Copy the exact endpoint secret again, save it as `SAFEPAY_WEBHOOK_SECRET`, and redeploy.

### Image upload fails

- Confirm Cloudinary variables are in `ecom-backend`.
- Confirm the admin token is valid.
- Inspect `POST /api/admin/uploads/signature` and the subsequent Cloudinary upload request in DevTools.
- Confirm the selected file is an image and no larger than 12 MB.

### Emails do not arrive

- Confirm the Resend sending subdomain is verified.
- Confirm `EMAIL_FROM` uses that same verified domain.
- Check Resend logs and the order's `NotificationLog` rows.
- Resend test recipients can be used during development before emailing real customers.
